一、部署拓扑

① 每台开发机（N 台，每台各装一份；客开代码与 JDK 都在本机）
浏览器访问 http://localhost:3030；局域网内其他设备也能访问（注意安全）

cc-web.exe :3030

  • Rust + Actix-Web，单文件 exe；前端资源编译期内嵌
  • 聊天页（多助手/分屏/队列）+ 补丁中心 15 个页签 + 3 个详情页
  • 每条消息起一个 claude 子进程（--resume 延续上下文、bypassPermissions）
  • 本机 HTTP 接口：/api/agent/*、/api/files/*、/api/adapt/*、/api/node/runs、/api/version、/api/update/*

本机状态与工具

  • ~/.cc-web/：sessions.json（会话）、node_runs.json（智能开发清单）、adapt_runs.json（适配记录）、logs/
  • ~/.claude/settings.json：模型网关凭证（模型下拉的来源）
  • ~/.claude/skills/：java-compiler-mcp、diff-report
  • 分发包里的 mcp-servers.json：java_compiler_mcp（stdio）+ patch_source（http）
  • <cc-web目录>\temp\adapt\<runId>\<seq>\：适配补丁解压目录
HTTP（JWT Bearer）：补丁检索 / 上传 / 分析 / 流程 / 账本上报 / 检查更新
② 服务器 A（管理员维护；标品源码只有这一份）

patch_search :13587

  • FastAPI + aiomysql；全部接口 JWT 鉴权
  • 补丁库（上传/检索/详情/下载）、管理员批量分析（claude 子进程，可配并发）
  • 流程引擎：流程/提示词/模板 → 运行（本地步骤靠 execution_token 认领）
  • 三类只写账本：problem_run、problem_run_session、patch_adapt_run/item
  • 产品/版本字典（逻辑删除）、产品环境变量（按人隔离）
  • 发版：data/ccweb-update/<版本号>/<平台>/ + latest.json

patch_source MCP :13589

  • 标品源码只读检索（grep / read_file / glob / stat_path / list_roots）
  • roots 按 <产品>/<版本> 挂（CFR 反编译产物）
  • 检索口径：path 必须写包级路径（全树扫 20s+，包级 <0.5s）
  • 独立审计日志 mcp_audit.log：记"读了/搜了哪些文件"

MySQL 10.4.122.21/patch

  • 18 张表（无外键约束，引用关系由应用层维护）：补丁库 / 用户与菜单权限 / 产品版本字典 / 流程引擎（6 张） / 产品环境变量 / 三类账本
  • 本机开发机上没有 mysql 客户端；迁移用 patch 环境的 python + pymysql 跑
注：开发机之间的会话/清单互不共享（本机清单是事实来源）；服务器只保存摘要账本，供跨机器查询。

二、主要数据流

① 补丁入库 → 可检索

  1. 开发机在「补丁上传」拖入 zip/rar → 浏览器直传 patch_search（multipart）
  2. patch_search 存进补丁库目录、写 patch_info（status=0 待分析）
  3. 管理员在「待分析补丁」勾选 → 服务器 A 的 claude 逐个分析（并发可配）→ 写 analysis_result / class_name / keyword、status=2
  4. 开发机在「普通检索」按名称/描述/类名/关键词检索（status=2 才进结果）

② 智能开发（问题解决节点）—— 两阶段同一 claude 会话

  1. 新建：填问题描述 / 触发 URL / 选产品环境变量 / 补丁输出路径 → cc-web 建会话（cwd = 客开工程根）
  2. 阶段一：claude 只读分析客开工程 + 用 patch_source 查标品 → 改动只写 <输出目录>\step01\work；走 java-compiler-mcp 打补丁 zip、生成 diff-report 对比报告
  3. 用户在详情页判定「已解决 / 未解决」；未解决可补日志重跑（step02、step03…）
  4. 阶段二：把暂存目录同步回客开工程、打去日志的干净补丁（成败以 合并说明.md 首行判定）
  5. 全程状态只写本机 node_runs.json；摘要上报 problem_run；已解决时完整会话存档 problem_run_session

③ 补丁适配 —— 逐个补丁合并进客开工程

  1. 入口：适配页签拖入多个补丁；或「普通检索」列表点「适配」（cc-web 直连补丁中心下载，带进度条）
  2. 填每个补丁的问题描述 + 选产品环境变量（自动带出客开工程目录）→ 检查 git 状态并强确认
  3. cc-web 后台线程串行跑：每轮 = 一条提示词 → claude 合并（对照物只有"补丁源码 vs 客开工程源码"）
  4. 每个补丁跑完停在「待确认」→ 详情页点「继续下一步 / 一键跑完剩余 / 重试失败 / 中止」
  5. 记录在本机 adapt_runs.json + 服务器 patch_adapt_run/item；「查看会话」可在聊天页实时围观（只读）

④ 智能分析（可配置流程）

  1. 选流程模板 + 填业务需求 → patch_search 引擎建运行（workflow_run / workflow_run_step）
  2. 服务器步骤：服务器 A 的 claude 执行；本地步骤：生成 execution_token，客户端 claim-local 认领后由本机 cc-web 跑（/api/local-claude/execute）
  3. 每步产出 结论.md / 摘要.md 入库；每步完成需点「确认下一步」
  4. 步骤用 {{flow:x.result}} / {{step.N.context}} 引用前序结果

⑤ 客户端自更新

  1. 管理员在「版本发布」上传各平台程序 → 服务器写 <版本号>/<平台>/，可「设为最新」
  2. 开发机登录后自动查一次 + 顶栏「检查更新」手动查：本机版本号 ≠ 最新版本号 → 提示更新（sha256 只做下载校验）
  3. 点「立即更新」→ cc-web 下载到 <原名>.new → 校验 → 写 update-cc-web.bat → 本进程退出
  4. 脚本反复尝试替换（最多 60 次）+ 备份 .bak + 设 CC_WEB_MCP_CONFIG + 重启；每步写 update-cc-web.log
  5. macOS 不自动替换：下载校验后加 0755 留在原地，提示手动替换后重启
